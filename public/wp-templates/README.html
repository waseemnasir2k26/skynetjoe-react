SkynetLabs · WordPress Paste Kit

Move a Next.js page into WordPress without breaking it.

Every route on app-mauve-eta-66.vercel.app is also exported as a standalone, self-styled HTML file at /wp-templates/<slug>.html. Open one, right-click → View Source, copy the full markup, and paste it into WordPress using one of the three methods below. The CSS is scoped to a .wn-<slug> wrapper so your theme's styles can't bleed in.

Last sync: Files in /wp-templates/ are regenerated automatically every npm run dev and npm run build via the scripts/sync-wp-templates.mjs hook. Run npm run sync-wp to force a sync.

1. Three ways to paste into WordPress

Method A — Page Editor + Custom HTML block easiest

  1. WP admin → Pages → Add New.
  2. Title the page (suggested titles below).
  3. Add a Custom HTML block (Gutenberg) or switch the Classic editor to the Text tab.
  4. Paste the entire <style>...</style> + body markup from the /wp-templates/<slug>.html file. Skip the outer <html>/<head>/<body> tags — WordPress provides those.
  5. Publish. Verify on the front-end. If your theme injects a sidebar, switch the page template to a full-width or "Empty" template.

Method B — Save as a page template recommended for permanence

  1. SSH/SFTP into the WP install and open the active theme directory (e.g. wp-content/themes/skynetjoe/).
  2. Create a file named page-<slug>.php (e.g. page-contact.php).
  3. Paste this wrapper, then paste the HTML body where indicated:
<?php
/* Template Name: SkynetLabs <Slug> */
get_header(); ?>
<main class="skynetlabs-page">
  <!-- PASTE content/<slug>.html HERE (style block + body markup, no html/head/body tags) -->
</main>
<?php get_footer(); ?>
  1. WP admin → Pages → Add New → in the Page Attributes sidebar, pick SkynetLabs <Slug> as the template.
  2. Publish.

Method C — Functions.php custom block / shortcode advanced

Drop this into functions.php for a reusable [skynetlabs slug="contact"] shortcode that pulls the template from the file system on every request — easier to update later:

<?php
add_shortcode('skynetlabs', function($atts) {
    $atts = shortcode_atts(['slug' => ''], $atts);
    $slug = sanitize_file_name($atts['slug']);
    if (!$slug) return '';
    $path = get_stylesheet_directory() . '/skynetlabs-templates/' . $slug . '.html';
    if (!file_exists($path)) return '<!-- skynetlabs: missing ' . esc_html($slug) . ' -->';
    return file_get_contents($path); // already-scoped CSS, schema, layout
});

Then drop the HTML files into wp-content/themes/<theme>/skynetlabs-templates/<slug>.html and reference them anywhere with [skynetlabs slug="contact"].

3. Style isolation — why CSS won't bleed

Every template wraps its content in a unique .wn-<slug> class (e.g. .wn-contact, .wn-aeo-guide). All selectors in the embedded <style> block are scoped to that prefix:

.wn-contact h1 { ... }
.wn-contact .hero { ... }
.wn-contact .btn-primary { ... }

This means the active WordPress theme's h1, .btn, or container styles cannot cascade into the pasted markup, and vice-versa. Do not rename the wrapper class when pasting — if you do, every rule in the <style> block stops matching.

4. Images — two options

Templates reference images either as /img/... (Next.js public assets) or as full Unsplash/CDN URLs. Pick one of these on paste:

  1. Option A — Upload to WP Media (recommended for long-term). Upload each /img/foo.jpg to Media Library, then find/replace src="/img/foo.jpg" → src="https://skynetjoe.com/wp-content/uploads/2026/05/foo.jpg" in the pasted HTML.
  2. Option B — Hotlink the Vercel deploy (zero work). Find/replace src="/ → src="https://app-mauve-eta-66.vercel.app/ in the pasted HTML. Images keep loading from the React build. Trade-off: if you ever sunset the Vercel project, the images break — keep the project live or migrate before deleting.

5. JSON-LD schema — already inline

Every template ships its own <script type="application/ld+json">...</script> block (Article, FAQPage, BreadcrumbList, Organization, Person, etc.). The WordPress Custom HTML block and Text mode editor both preserve <script> tags as-is — no schema plugin needed.

Plugin conflict warning: if Yoast / Rank Math / All-in-One SEO is installed and outputting Article/WebPage schema for the same URL, you'll have duplicate schema blocks. Either (a) disable schema output for these specific page slugs in your SEO plugin, or (b) strip the inline JSON-LD before pasting. Don't ship both — Google's Rich Results test will flag the conflict.

6. Pre-flight checklist

  1. Page template picked (Method A, B, or C).
  2. Page slug matches the suggested WP URL exactly (so internal links from other templates resolve).
  3. Image strategy chosen (uploaded to Media or hotlinked to Vercel).
  4. SEO plugin schema disabled on the URL if pasting inline JSON-LD.
  5. Page template set to Full Width / No Sidebar (the templates supply their own container).
  6. Tested on mobile — wrap classes don't break the WP theme's responsive grid.
  7. Rich Results test pass: search.google.com/test/rich-results.
