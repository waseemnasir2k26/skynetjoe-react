## P0 — Fix immediately

### P0-1. Missing OG/Twitter share image — `/og-default.png` 404s
- **File:** `src/app/layout.tsx:37` and many child pages
- **Issue:** `images: [{ url: "/og-default.png" ... }]` is referenced from root layout AND inherited by every page. The file does NOT exist in `/public/` (only `waseem-portrait.jpg` does). Every LinkedIn/Twitter/Slack share renders a broken image.
- **Fix:** Create `src/app/opengraph-image.png` (Next.js v16 file-convention OG image) OR drop a 1200×630 PNG at `/public/og-default.png`. Until then, fall back to `waseem-portrait.jpg` for OG to avoid 404. **FIX APPLIED — changed default to existing image.**

### P0-2. Missing `/apple-icon.png`
- **File:** `src/app/layout.tsx:56`
- **Issue:** `apple: "/apple-icon.png"` references a file that doesn't exist. Privacy-policy & terms JSON-LD also reference `/apple-icon.png` as publisher logo.
- **Fix:** Drop a 180×180 PNG, OR remove the apple-icon line and let Next.js v16 file convention pick it up (it's optional). **FIX APPLIED — removed broken reference.**

### P0-3. ~~STATES count mismatch~~ — RESOLVED, no issue
- **File:** `src/lib/states.ts`
- **Initial finding:** Believed STATES held 50 entries vs copy promising 48.
- **Re-verification:** State entry count is actually **48** (matches copy). False alarm — initial grep counted unrelated `slug:` occurrences in helper functions. ✓

## P1 — Fix soon

### P1-1. ~~`llms.txt` does not exist~~ — RESOLVED, no issue
- **File:** `public/llms.txt`
- **Initial finding:** Believed missing. **Re-verification:** File already exists at `public/llms.txt` (49 lines, well-structured per llmstxt.org draft spec, dated 2026-05-22). Includes core pages, services, proof, author, tools. ✓
- **Minor opportunity:** Current `llms.txt` lists Locations but not individual state URLs. A future expansion could enumerate all 48 state pages. Did not auto-fix.

### P1-2. Services index page (`/services`) has no JSON-LD
- **File:** `src/app/services/page.tsx:24` (just dumps HTML, no JsonLd)
- **Issue:** No `ItemList` or `OfferCatalog` schema for the 16 services. Loses an easy AEO citation win.
- **Fix applied:** Added `OfferCatalog` schema covering all 16 services. **FIX APPLIED.**

### P1-3. Services `[slug]` page has no Service JSON-LD
- **File:** `src/app/services/[slug]/page.tsx:40`
- **Issue:** Only metadata + HTML. No `Service` schema, no `BreadcrumbList`. Each of the 16 service pages loses structured data.
- **Fix applied:** Added Service + BreadcrumbList JSON-LD. **FIX APPLIED.**

### P1-4. About page has no Person/AboutPage JSON-LD
- **File:** `src/app/about/page.tsx:24`
- **Issue:** Page is biographically rich (Lahore→Singapore→Bali, 180 workflows, etc.) but ships no `Person` or `AboutPage` schema. Author-waseem-nasir page has none either.
- **Fix applied:** Added `Person` + `AboutPage` schema to both `/about` and `/author/waseem-nasir`. **FIX APPLIED.**

### P1-5. Long-form content pages missing Article/FAQPage schema
- **Files:** `aeo-guide/page.tsx`, `glossary/page.tsx`, `faqs/page.tsx`, `n8n-vs-zapier/page.tsx`, `portfolio/page.tsx`, `case-studies/page.tsx`, `tools/page.tsx`, `pricing/page.tsx`
- **Issue:** All ship metadata but NO JSON-LD. AEO guide, FAQs, and n8n-vs-zapier are exactly the kind of content LLMs love to cite — but without `Article`/`FAQPage`/`DefinedTermSet` schema, citation likelihood drops.
- **Fix applied:** Added Article + breadcrumb schema to all 8 pages, plus `FAQPage` schema to `/faqs` and `DefinedTermSet` to `/glossary`. **FIX APPLIED.**

### P1-6. Blog post `[slug]` page missing Twitter card metadata
- **File:** `src/app/blog/[slug]/page.tsx:17-36`
- **Issue:** `generateMetadata` sets OG but no `twitter` field. Inherits root default which uses non-existent `og-default.png`.
- **Fix applied:** Added `twitter` metadata with article-specific card. **FIX APPLIED.**

### P1-7. Service `[slug]/in/[state]` canonical is RELATIVE
- **File:** `src/app/services/[slug]/in/[state]/page.tsx:43`
- **Issue:** `canonical: ` /services/${svc.slug}/in/${st.slug}`` — relative. Next.js resolves via metadataBase, but spec asked for absolute URLs.
- **Fix applied:** Changed to `${SITE.url}/services/${svc.slug}/in/${st.slug}`. **FIX APPLIED.**

### P1-8. Locations `[state]` canonical is RELATIVE
- **File:** `src/app/locations/[state]/page.tsx:32`
- **Issue:** Same as above.
- **Fix applied:** Changed to absolute URL. **FIX APPLIED.**

### P1-9. Blog `[slug]` canonical is RELATIVE
- **File:** `src/app/blog/[slug]/page.tsx:24`
- **Issue:** Same.
- **Fix applied:** Changed to absolute URL. **FIX APPLIED.**

### P1-10. Sitemap incomplete service×state matrix
- **File:** `src/app/sitemap.ts:59` — `PROTOTYPE_STATE_MATRIX = ["california"]`
- **Issue:** Only 16 svc×state combos emitted (California only). 16×50 = 800 potential URLs. Audit spec mentions "future 768 svc-state combos" so this is by design but flagged.

## P2 — Nice to have

### P2-1. Description char-count
- All page descriptions are ≥120 chars **except** the service `[slug]` dynamic pages which use `svc.desc` (the 50-char teaser from `site.ts`, e.g. "Workflow automation that runs while you sleep" = 47 chars).
- **Fix applied:** Wrapped `svc.desc` in a fuller template that hits ≥140 chars per service page. **FIX APPLIED.**

### P2-2. Sitemap `lastModified` uses `new Date()` for static routes
- **File:** `src/app/sitemap.ts:31`
- **Issue:** Every build mutates `lastmod`. Google may re-crawl unnecessarily.
- **Recommendation:** Use a fixed deploy date constant. Not auto-fixed.

### P2-3. Hero-lab and gradient-lab correctly `noindex`
- Confirmed both internal pages have `robots: { index: false, follow: false }`. ✓

### P2-4. Robots.ts: consider adding `Bingbot` explicitly
- Currently only AI bots are explicit. Bingbot inherits from `*` (allow /) — already correct, no action needed.

### P2-5. No `<Image priority>` audit risk
- Hero image in `/contact` uses `priority` correctly. Other pages render HTML content directly so no Next/Image CWV concerns. ✓

### P2-6. Blog `og:image` for posts
- Blog posts have `coverImage` field on `Post` type but never emit it as OG image. Result: all blog posts share the same broken `/og-default.png`.
- **Recommendation:** Once cover images exist in `/public/blog/`, wire them into `generateMetadata`. Not auto-fixed (depends on assets).
